ダビマス配合研究所 v3.3｜生産用UI整理・所持315頭を初期登録
作成日：2026-11-06
改修元：v3.2（GitHub 2026-11-06 の app.js/index.html/sw.js と同一のアーカイブを使用）

■ 変更点
1. 日常メニューは「自動設計・種牡馬図鑑・繁殖牝馬・自家製馬・保存プラン・データ管理」の6つ。
   旧「能力記録」の独立メニューを外し、工程別の実測・ゲノム記録は保存プラン内に残しています。
2. 保存プランの既存9工程は1行ずつ表示し、タップすると各工程の入力欄を開けます。
   必要性別・予定配合・作業状況は閉じた状態でも確認できます。
   実測因子を反映した血統、候補因子のスナップショット、本気型の仕込みは折りたたみ。
3. 旧研究用の比較・配置変更・仮連結用コントロールは通常の保存プラン画面から外しました。
   仮馬の一覧重複も解消し、実際に生産した馬の記録だけを必要に応じて表示。
   既存の配合計算関数や仮馬連結の保存形式は変更していません。
4. 所持済315頭（2026-11-06の確認データ）を、個人用PWAの初期チェックとして組込み。
   既に各ブラウザでチェック/解除した決定は維持します。権利0でも所持扱い。
   公開マスターCSVの実体はIndexedDBに残り、初回の別PCには別途取り込みが必要です。
5. 「データ管理 → 研究用データだけ初期化」を追加。
   「初期化」と入力した場合のみ、実行前に現在のJSONを自動書き出しし、
   配合プラン、仮馬、自家製馬、能力記録をゼロにします。
   所持チェック・ユーザー追加の種牡馬・牝馬ランク・牝馬お気に入り・公開マスターは保持。
   GitHub更新のみでは既存端末のプランを自動消去しません。
6. 別ファイルの「dabimas_315_clean_start_v33.json」は、所持315頭のチェックを保持した
   プラン0件・仮馬/自家製0件・能力記録0件の専用初期化ファイルです。
   v3.3の「JSON読み込み」では旧プランと統合せず置き換える挙動です。
   旧バージョンで読み込んだ場合は統合される可能性があるため、先にv3.3へ更新してください。

■ 初期化の手順（本番開始前に一回だけ）
(1) v3.2の「データ管理」から念のためJSONフルバックアップ。
(2) GitHub直下へ本ZIPの6ファイルを上書き。PWAでv3.3表示を確認。
(3) 「データ管理」→「研究用データだけ初期化」→「初期化」と入力。
    操作の前に自動バックアップのダウンロードが開始されるので保管してください。
(4) 「保存プラン」が0件、「自家製馬」が0頭、「所持チェック」が315頭であることを確認。
    別PCでは公開CSVの取り込み・復元状況も確認してください。
(5) 以降は「自動設計」でマイルド型9工程を作成。

■ データと公開について
・既存の localStorage キー dabimas_lab_v02_state、IndexedDB dabimas_lab_v02/db は変更せず保持。
・公開馬マスターのCSVは本ZIPに同梱しません。元の公開ソースから端末に取り込みます。

  運用している場合は、所持リストの一部を含むソースコードを第三者が閲覧できます。
